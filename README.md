# Figma Local MCP

Локальный MCP-сервер и плагин для Figma Desktop. Объединённая версия **2.3.0**: инструменты из архива 2.2.0 и локальные доработки SlavaZhivaev.

## Что входит

- 22 MCP-инструмента: чтение и изменение макетов, снимки, CSS, экспорт, импорт HTML, библиотеки, переменные, прототипы и code layer.
- Несколько открытых файлов: выбор по имени или идентификатору сессии.
- Общий сервер для нескольких MCP-клиентов, постоянный адрес и ключ подключения.
- Чтение, публикация, ответы и удаление комментариев через Figma REST API.
- Защита от повторного выполнения команд и запись с контролем неизвестного результата.

## Установка

Нужны Python 3.9+ и Node.js для проверок установщика.

```bash
git clone https://github.com/SlavaZhivaev/figma-local-mcp.git
cd figma-local-mcp
bash install.sh
```

Если MCP ещё не зарегистрирован в Codex:

```bash
codex mcp add figma_local -- python3 -u "$HOME/figma-local-mcp/server.py"
```

В Figma Desktop импортируйте `~/figma-local-mcp/plugin/manifest.json` через Plugins → Development → Import plugin from manifest. Перезапустите MCP-клиенты и запустите плагин. Адрес и ключ для первого подключения выдаёт `figma_status`. Секреты хранятся вне репозитория, в `~/.figma-local-mcp/`.

# Figma Local MCP

Локальный MCP-сервер и плагин: ИИ-агент (Claude Code, Codex и другие MCP-клиенты) читает и правит **файл, открытый у вас в десктопной Figma прямо сейчас**. Токен Figma не нужен, платное место не нужно, файл никуда не выгружается — агент и плагин общаются через `127.0.0.1`.

Версия 2.2. Python 3.9+, без сторонних зависимостей. Только десктопная Figma, файл открыт с правом редактирования.

## Что умеет

| Задача | Инструменты |
|---|---|
| Связь, кто и где | `figma_status` — подключение, файл и его ключ, страницы, выделение, видна ли Figma |
| Страницы | любой инструмент берёт id слоя с любой страницы; `figma_pages` — страницы с верхними фреймами, `find` — поиск по всему файлу, `focus` — показать слой |
| Читать макет | `figma_read` — дерево слоёв со стилями · `figma_screenshot` — картинка слоя · `figma_pages` — страницы |
| Строить и править | `figma_apply` — до 500 операций: создать, клонировать, поправить, удалить; Auto Layout, Grid, обводки, тени, градиенты, SVG, картинки из файлов, шейдеры |
| Дизайн-система файла | `figma_library` — переменные, стили, компоненты, шейдеры, анимации; в `figma_apply` — инстансы, стили, привязка переменных, свойства компонентов |
| Макет → код | `figma_design_context` — готовая HTML/CSS-страница со снимком, картинками и SVG · `figma_css` · `figma_variable_defs` · `figma_assets` · `figma_motion` |
| Код → макет | `figma_import_html` — HTML в редактируемые слои |
| Прототипы из кода | `figma_code_layer` — слой кода из HTML, папки, GitHub или фреймов макета · `figma_code_layer_run` — живой запуск и снимок состояния в макет · `figma_code_layer_sync` — правки текста в код · `figma_code_layer_get` — исходник и правки, указанные в прототипе |
| Проверка | `figma_a11y` — контраст, мелкий текст, маленькие нажимаемые области |
| Прототип без плагина | `figma_prototype` — обычный прототип Figma (▶, Present, ссылка) · `figma_code_layer_get` с `folder` — папка сайта для браузера |
| Экспорт | `figma_export` — PNG, JPG, SVG, PDF, MP4, GIF, WebM |
| Комментарии | `figma_comments` — через REST API Figma и личный токен (в Plugin API комментариев нет) |

Сервер помечает инструменты «только чтение» и «изменяет файл», как облачный Figma MCP, — клиент может разрешать безопасные без вопросов. Есть встроенная инструкция для агента и готовые сценарии (MCP prompts): обзор файла, макет в код, проверка доступности, прототип из HTML, разбор комментариев.

### Чем отличается от облачного Figma MCP

| Облачный | Здесь |
|---|---|
| `get_design_context`, `get_metadata`, `get_screenshot`, `get_variable_defs`, `download_assets`, `get_motion_context`, `export_video`, `search_design_system` (по файлу), `whoami` | есть, локально |
| `send_code_to_figma` и инструмент {} Code (Code Layers) — когда они вам доступны, `figma_code_layer_get` с `archive` готовит архив для облачного `send_code_to_figma`: получается настоящий слой кода (импорт без кредитов ИИ); плагин такие слои видит (`CODE_INSTANCE`), двигает, переименовывает и снимает | локальный слой кода: из HTML, папки, GitHub или выделенных фреймов; живой запуск, многостраничные прототипы, «указать и поправить», снимок состояния в макет (Extract designs), перечитать из папки (Reload) |
| HTML в слои | `figma_import_html` |
| `use_figma` (произвольный JS) | нет — остановлено проверкой безопасности |
| `create_new_file`, `upload_assets` | плагин сам файл создать не может; агент делает это облачным MCP (бесплатно, работает и с местом View), дальше — локально |
| `generate_image` (нейросеть, платно) | локально — иллюстрации, иконки и графики кодом (SVG, PNG через PIL); фото нейросетью — только облачный `generate_image` за кредиты Figma AI |
| Code Connect, Weave, генеративные плагины | нет — это облачные сервисы Figma |

## Установка

### Быстро (macOS, Linux)

```sh
bash figma-local-mcp/install.sh
```

Скрипт проверит Python, скопирует решение в `~/figma-local-mcp`, подключит сервер `figma_local` к Claude Code и Codex (если они есть) и положит скилл в `~/.claude/skills` и `~/.codex/skills`. Затем — один ручной шаг:

**Плагин:** Figma → Plugins → Development → **Import plugin from manifest…** → `~/figma-local-mcp/plugin/manifest.json`.

Перезапустите MCP-клиент, чтобы он увидел сервер.

### Вручную

```sh
claude mcp add figma_local -s user -- "$(command -v python3)" -u "$PWD/server.py"
codex mcp add figma_local -- "$(command -v python3)" -u "$PWD/server.py"
cp -R skill/figma-local ~/.claude/skills/
```

На Windows `install.sh` не работает: укажите полный путь к `python.exe` и `server.py`. Сервер запускает сам MCP-клиент — вручную его не запускайте.

### Комментарии (по желанию)

Figma → Settings → Security → **Personal access tokens**, доступ «File comments: read» и «File content: read». Сохраните токен одной строкой в `~/.figma-local-mcp/figma-token`. Это бесплатно; в чат токен не вставляйте.

## Первое подключение

1. Откройте файл в десктопной Figma и запустите плагин: Plugins → Development → **Figma Local MCP** (дальше — «Run last plugin», ⌥⌘P).
2. Попросите агента вызвать `figma_status` и вставьте адрес и ключ в окно плагина.

Ключ **постоянный** (`~/.figma-local-mcp/token`): вставляется один раз на компьютере. Дальше достаточно запустить плагин — он подключится сам и сам найдёт сервер, если тот занял соседний порт. Figma не разрешает плагинам запускаться самим, поэтому плагин открывается вручную раз за сеанс.

После подключения окно плагина — компактная карточка: статус, выделенный слой кода с «▶ Запустить», ссылка «Изменить подключение». Окно можно свернуть в полоску или скрыть — плагин продолжит работать.

## Прототипы из кода

**Слой кода** — фрейм `</> Название` на холсте. Внутри хранится полный исходник (до ~24 млн символов, переживает сохранение и копирование файла), поверх — превью из настоящих редактируемых слоёв.

- **Создать:** `figma_code_layer` с `html` или `path` (файл или папка проекта). Из папки берётся собранный `dist/`, `build/` или `out/index.html`; локальные CSS, JS, картинки и шрифты встраиваются; CDN (esm.sh, unpkg, jsdelivr, cdnjs, Tailwind CDN, Google Fonts) грузятся. Проекты на Vite/React — сначала `npm run build`.
- **Несколько страниц:** все `.html` папки упаковываются в один слой, превью — все страницы рядом, ссылки `<a href="step2.html">` работают при запуске.
- **Запуск:** выделите слой — в окне плагина «▶ Запустить». Страница работает с JavaScript, формами и ссылками; в шапке «назад» (Alt+←), выбор страницы, перезапуск, Esc закрывает. Код выполняется в изолированном фрейме без доступа к плагину, ключу и документу.
- **Правки в макете попадают в прототип.** При запуске плагин сравнивает экраны с тем, как их нарисовал: ничего не меняли — запускается код; только тексты — переносятся в код; блоки, цвета, размеры, новые элементы — прототип собирается заново из слоёв (ссылки и поля ввода сохраняются, собственный JavaScript страниц — нет). В шапке видно «из макета».
- **Ссылка у нового блока:** выделите блок внутри экрана — в окне плагина выберите страницу, куда он ведёт.
- **▶ и ⤢ над слоем на холсте**, как у слоёв кода Figma: ▶ играет прототип на месте — поверх экрана, в масштабе холста; ⤢ — большим окном.
- **Без плагина:** кнопка «Сделать прототип Figma» в окне плагина (или `figma_prototype`) собирает обычный прототип Figma — экраны, переходы по клику, точка старта; он играет кнопкой ▶ / Present и по ссылке у любого. Для браузера — `figma_code_layer_get` с `folder`: папка с отдельными страницами, работает со всем JavaScript.
- **Несколько прототипов:** каждый слой кода — отдельный прототип; запускается выделенный.
- **С GitHub:** `path` — ссылка на репозиторий (`/tree/ветка/папка` тоже). Клон лежит в `~/.figma-local-mcp/repos`, скрипты репозитория не запускаются; если нужна сборка, агент спросит, прежде чем собирать. `reload: true` с `id` перечитывает слой из папки или репозитория.
- **Из фреймов макета:** `frames` — экраны становятся страницами слоя кода, переходы прототипа Figma — ссылками; экраны, куда ведут переходы, добавляются сами.
- **Указать и поправить:** в окне запуска кнопка ◎ — кликните элемент и напишите, что поменять. Скажите агенту «сделай правки из слоя кода»: он прочитает их через `figma_code_layer_get`, поправит код и обновит слой.
- **Снимок в макет:** кнопка 📷 в окне запуска (или `figma_code_layer_run` с `extract`) — текущее состояние страницы с введёнными данными и открытыми меню становится редактируемыми слоями в секции «◉ Снимки» под слоем. Снимки по шагам складываются в ряд — получается сценарий.
- **ИИ может пройти прототип сам:** `figma_code_layer_run` с `click` (текст кнопки или селектор), `fill`, `page`.

## Figma в фоне

Держать Figma открытой не нужно. Команды доходят сразу и в фоне: плагин держит открытый запрос к серверу, а не опрашивает его по таймеру, который Figma в фоне замедляет до раза в минуту. Для экспорта, снимков и отрисовки HTML Figma нужен экран, поэтому сервер сам выводит её вперёд — нужную вкладку, даже если Figma скрыта (Cmd+H) или свёрнута, — и через пару секунд возвращает приложение, в котором вы были. Отключить — `FIGMA_AUTO_RAISE=0`.

Несколько сеансов ИИ (два окна Claude, Claude и Codex) — у каждого свой сервер. Плагин сам переходит к тому сеансу, который его просит, если другой сейчас ничего не делает.

- **Клонируйте готовое** из файла (шапки, карточки, компоненты) вместо рисования примитивами.
- **Большие страницы читайте сверху:** `figma_read` с `depth: 0`, потом нужная ветка.
- **Проверяйте снимком** каждый собранный экран.

## Как это устроено

- Сервер — MCP по stdio и маленький HTTP-мост на `127.0.0.1:38471–38474`, закрытый ключом. Плагин опрашивает мост и забирает команды по одной; каждая команда доставляется один раз.
- **Самообновление:** когда `server.py` меняется, сервер в паузе между командами перезапускается в том же соединении (тот же порт и ключ) и сообщает клиенту новый список инструментов — `/mcp` не нужен. Отключить — `FIGMA_NO_RELOAD=1`.
- Каждый MCP-клиент поднимает свою копию сервера на свободном порту; плагин говорит с одной копией за раз. При перезагрузке плагин отпускает связь, и новый экземпляр подключается сразу.
- HTML отрисовывается в окне плагина, в изолированном фрейме; раскладка и стили снимаются и превращаются в слои в основном потоке плагина.
- Пакет `figma_apply` — один шаг отмены (Cmd+Z). Отката при ошибке нет: ответ сообщает, что успело примениться.

## Ограничения

- Нет: создания переменных, стилей и наборов вариантов, правки Motion-анимаций, произвольного JavaScript, Code Connect, генерации картинок, создания файлов, настоящих Code Layers Figma (их нет в Plugin API).
- Импорт HTML: раскладка абсолютная; внешние картинки и шрифты не грузятся (кроме CDN из списка); шрифт, которого нет в системе, заменяется.
- Чтение — до 200 узлов и глубины 4 за раз.
- На тарифе Starter — не больше 3 страниц в файле.

## Изменения 2.2: подключение и очередь команд

- Клиент соединения вынесен в `plugin/src/connection.js`. `plugin/src/ui.html` — исходник интерфейса; `python3 build_plugin.py` создаёт готовый `plugin/ui.html`. Для установки Node.js и сборщик JavaScript не нужны.
- Повторное подключение отменяет прежние сетевые запросы. Поздние ответы прежнего подключения игнорируются.
- Готовый результат отправляется одним запросом; при сетевом сбое сохраняется и повторно отправляется только исходному серверу. Сама команда повторно не исполняется.
- Пока команда выполняется, отдельный heartbeat поддерживает связь без получения следующей команды. На другой сервер плагин переключается только без незавершённой команды.
- Очередь сервера вынесена в `bridge_queue.py`. При закрытии окна плагина команда завершается явной ошибкой; уже доставленная правка не передаётся новому окну.
- После неизвестного результата правки доступны чтение и снимки для проверки. Новые правки запрещены до позднего результата или явного `figma_status(unblock=true)` после осмотра.
- Дубликаты результатов подтверждаются без влияния на последующие команды. Поздний результат старой правки не снимает блокировку новой.
- Установщик сначала проверяет сборку и тесты. `deploy.py` заменяет файлы атомарно, сохраняет прежние версии и восстанавливает уже заменённые файлы при ошибке установки. Настройки клиентов и ключи он не меняет.

Проверки разработчика:

```sh
python3 build_plugin.py --check
PYTHONWARNINGS=ignore FIGMA_AUTO_RAISE=0 python3 -m unittest -q
node tests/test_connection.mjs
```

JavaScript-тесты можно запускать встроенной средой Node агента, если отдельного Node.js на компьютере нет. Для серверных тестов нужны локальные TCP-соединения; запрет на открытие локального порта в среде запуска не означает ошибку плагина.

Восстановление конкретной установки:

```sh
python3 deploy.py --restore /полный/путь/к/.backups/папке-копии
```

Восстановление останавливается, если файлы менялись после обновления, чтобы не затереть последующие правки. При изменении файлов плагин Figma может перезапуститься; повторно вставлять сохранённый ключ обычно не требуется.
